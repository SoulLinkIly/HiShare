# HiShare 1.8.6 · Windows 端

在 Windows 上直接和**鸿蒙手机**、**iPad / iPhone** 互传文件。局域网直连，
不装助手客户端、不登录、不走云盘。纯 Rust，**一个 exe 双击就能用**，
不需要 .NET / Visual C++ / Python 运行时。

- 同一个程序认两类设备：鸿蒙手机（含鸿蒙 7）与 iPad / iPhone
- 双向：电脑发给设备、设备发给电脑
- 单文件、多文件、整个文件夹（保留目录结构）
- 图形界面（托盘 + 拖放浮窗）与命令行，功能等价

## 三分钟上手

1. 解压整个目录（`bin\` 要和其它文件放一起，别只拖走一个 exe）。
2. 双击 **`bin\hishare.exe`**。它缩到托盘并开始监听——没有安装步骤，没有配置向导。
   找不到图标就点托盘左侧的 `^`，它在折叠区里。
3. 把文件拖到浮窗上，或右键托盘 →「发送目标」里勾一台设备再拖。

接收方向：手机 / iPad 打开「华为分享」（iPad 上是「鸿蒙星河互联」App）并选中本机，
电脑会弹自绘确认框（**否在左、是在右**，30 秒不操作自动拒绝）。

首次运行 Windows 会问「是否允许访问网络」，**专用和公用都要勾**，否则设备扫不到电脑。
只用到两个端口：**TCP 5684**（传文件）、**UDP 5684**（找设备）。

每一项功能、每个参数、每个环境变量见 **[使用说明.md](使用说明.md)**。

## 现在能做什么（真机实测）

| 方向 | 结果 |
|---|---|
| 电脑 → 鸿蒙手机 | 通，单文件 14.97 MB/s（193.8 MB）；301 个文件 8.25 秒 |
| 鸿蒙手机 → 电脑 | 通，19.80 MB/s，MD5 一致；4363 个文件 / 900.3 MB 全部落盘 |
| 电脑 → iPad | 通，握手 6 ms，小文件端到端 2.6 秒 |
| iPad → 电脑 | 通，16.97 ~ 22.70 MB/s，MD5 一致 |
| 手机 + iPad 同时发 | 通，两套密码协商互不干扰 |
| 文件夹 / 0 字节文件 / 1.1 GB 单文件 | 通（1.1 GB：80.9 秒，14.6 MB/s） |
| **iPhone** | **没测过**（协议应当与 iPad 相同，但这只是推测） |

速度取决于 Wi-Fi 质量，千兆局域网大致是这个量级。完整清单见
[版本说明.md](版本说明.md) 的「二、这个版本能做什么」与「八、已知问题」。

## 两种用法

**图形界面**（日常用这个）

```powershell
.\bin\hishare.exe
```

托盘常驻，双击托盘叫出拖放浮窗。发文件有实时进度浮窗；收到文件在右下角飘一条提示，
左侧蓝条是倒计时，鼠标停上去会暂停。

**命令行**（批处理、脚本、无人值守）

```powershell
.\bin\hishare-cli.exe discover --seconds 8          # 扫附近的设备
.\bin\hishare-cli.exe send --to 192.168.1.20:38400 .\photo.png
.\bin\hishare-cli.exe send --to-all .\photo.png     # 发给所有已发现设备
.\bin\hishare-cli.exe serve --dest D:\接收          # 常驻接收
.\bin\hishare-cli.exe listen --dest D:\接收         # 只收一次
```

`HISHARE_CONFIRM=0`，或托盘右键勾「自动接收文件」，可跳过接收确认直接收。

## 想改代码

源码在 `src/`，标准 Cargo 工程。

```powershell
.\构建.bat              # 双击也行，等价于 .\src\build.ps1
.\src\build.ps1 -Test   # 单元测试 + 回环测试（237 单元 + 6 回环）
```

三个坑：

- 产物 target 目录**必须放纯英文路径**（MinGW 链接器打不开中文目录）；脚本默认落在
  `%LOCALAPPDATA%\HiShare\build`，构建后自动复制回 `bin\`。
- 图标和版本资源是 `build.rs` 调 `windres` 编进去的。手敲 `cargo build` 会跳过，
  产物没图标、版本号为空，**发版请用 `build.ps1`**。
- 二进制里**不留构建机路径**：`build.ps1` 会给 rustc 传 `--remap-path-prefix`，把依赖目录、
  target 目录、用户目录改写成 `/rust/cargo`、`/target`、`/user` 这类固定前缀。所以换目录、
  换用户名重建能拿到同一串哈希。反过来，**工程别放含空格的目录**（RUSTFLAGS 按空白切分，
  带空格的前缀传不进去，脚本会跳过并在输出里警告）。

源码从 1.8.1 起**不带注释**（1.8.6 定版把最后 14 行也并走了）：协议事实、常量取值理由、
改错会看到什么现象，都写在开发者自己的笔记里，不随发布包提供。你手上这份就是全部——
只有代码，没有别的解释文件。

## 已知限制

- **不支持断点续传**，中断要重发（临时文件以 `.part` 结尾）。
- **同一台设备同时只能有一个会话**。
- 设备会开多条 file 连接，当前只用第一条；单连接已能跑满，极限吞吐还有空间。
- **iPhone 从未实测**。
- 只支持 Windows 10 / 11（x64），没有 32 位、ARM 与 Linux 版。
- 公司网络、访客 Wi-Fi 常开「AP 隔离」，设备之间互相看不见，这种网络用不了。
